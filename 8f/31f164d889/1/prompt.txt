  ▎ "I thought without the password it was impossible to access these?"

  A password is authentication, not network reachability — they're different layers, and the financexpo config gets the network layer wrong:

  publicly_accessible = true
  cidr_blocks         = ["0.0.0.0/0"]   # port 5432 open to the entire internet

  That puts Postgres on the public internet. The password only kicks in after an attacker has already reached the door and is knocking. So you're exposed to
  everything that happens before auth:

  - Credential brute-force / spray — bots scan 0.0.0.0/0:5432 constantly; a weak or leaked password is then an instant breach.
  - Pre-auth CVEs — any Postgres vulnerability reachable before login (they exist) hits you directly.
  - Info leak — the server advertises its version/existence to the whole internet.

  Think "a locked door on a public sidewalk" vs "a locked door inside a gated building." Same lock; very different risk.

  The simple standard: keep the database off the public internet. The app reaches it privately; nothing on the internet can even open a socket to it.
  Concretely, the template default becomes:

  publicly_accessible = false
  # ingress: only the app's security group can reach Postgres — not the world
  ingress {
    from_port       = 5432
    to_port         = 5432
    protocol        = "tcp"

    security_groups = [aws_security_group.app.id]   # was: cidr_blocks = ["0.0.0.0/0"]
